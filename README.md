# 삽화가 (개인용) / LV-Illust

[English](README.en.md)

루미버스(Lumiverse)용 개인 확장. AI가 답변 중간에 `<pic ...>` 태그를 쓰면 그 자리에 NovelAI 그림을
넣고, 인물마다 등록해 둔 외형 프롬프트를 이름으로 찾아 NAI 인물별 프롬프트 칸(`characterTags`)에
넣는다.

> **개인용·비공개입니다.** 재배포·공개 라이선스를 걸어 두지 않았습니다. 사용은 본인(저장소 소유자)과,
> 본인이 직접 저장소를 공유한 대상으로 한정합니다. "배포"가 아니라 "내 서버에 설치"를 전제로 만들었습니다.

## 하는 일

| # | 기능 |
|---|---|
| F1 | 답변 생성 전, "그림이 필요하면 `<pic chars="이름" prompt="장면">` 태그를 써라"는 지시를 프롬프트에 끼워 넣는다. 위치·깊이·역할은 설정에서 고를 수 있다. |
| F2 | 생성이 끝나면 답변에서 `<pic>` 태그를 찾아 하나씩 그림으로 바꾼다. 한 답변당 최대 2장(설정 가능), 넘는 태그는 "건너뜀" 표시. 형식이 깨진 태그는 **원문을 절대 지우거나 요약하지 않고 그대로 둔 채** 바로 옆에 짧은 표시만 덧붙인다(메시지 길이는 줄지 않는다). |
| F3 | 태그 속 이름을 등록부에서 찾아(별칭 여러 개, 긴 이름부터, 대소문자·띄어쓰기 무시, 실제 띄어쓰기 경계가 있을 때만 부분일치 허용) 외형 프롬프트로 바꾸고 NAI 인물 칸으로 보낸다. 등록 안 된 이름·꺼 둔 인물은 AI가 쓴 묘사만으로 그린다. |
| F4 | 캐릭터 카드마다 인물 외형 등록부(이름들·**신체 특성**·**옷·장신구**·인물별 네거티브·켜기/끄기)를 둔다. 같은 카드의 모든 채팅이 공유한다. 등록부는 **빈 상태로 시작**하며, 미리 채워 둔 이름은 없다. |
| F5 | 그림을 메시지 속 태그 자리에 그대로 넣는다(`chat.updateMessage`). 실패/상한 초과는 각각 다른 표시로 남고, 원본 정보는 메시지 메타데이터에 보관되어 복구 가능하다. 생성은 루미버스의 `imageGen.generateNative`로 요청하며, 활성 메인 프롬프트 프리셋 + 활성 그림체(LoRA/스타일) 프리셋을 장면 프롬프트와 함께 적용한다(없으면 장면 프롬프트만). |
| F6 | 입력창 버튼 "삽화가 설정" 패널에서 이 채팅에 그려진 그림을 타일로 보고, 누르면 보낸 프롬프트·네거티브·인물 칸을 확인하고 "다시 그리기"를 누를 수 있다. 생성 중 메시지가 바뀌어(수정·스와이프) 그림을 넣을 자리가 사라지면, 그림을 버리지 않고 같은 패널에 상태/사유만(재시도 버튼 없이) 남겨 둔다. |

메인 프롬프트·그림체 프리셋·장면 자동 생성 같은 루미버스 기본 기능은 그대로 쓴다 — 이 확장은
"답변 속 그림 태그" + "인물별 외형 등록"만 더한다.

## 0.3.0 변경점 — 캐릭터 갤러리에 저장

- **그림 → 그림 타일 → 갤러리에 저장**을 누르면 현재 채팅의 캐릭터 갤러리에 기존 이미지를 연결한다.
  성공하면 **갤러리에 저장됨**으로 바뀌며 버튼이 비활성화된다. 기존 갤러리를 확인해 같은 이미지의 중복 연결을 막는다.
- 설정의 **생성 시 자동으로 갤러리에 저장**은 기본 **꺼짐**이다. 켜면 새로 생성하거나 다시 그린 그림 중
  저장된 이미지 ID가 있는 그림을 자동으로 연결한다. 갤러리 저장이 실패해도 답변 속 그림 전달은 계속된다.
- 그룹 채팅, 캐릭터가 없는 채팅, 저장된 이미지 ID가 없는 그림에서는 저장 버튼을 비활성화하고 이유를 표시한다.
- 로그인한 루미버스 브라우저에서 저장한다. 패널이 닫혀 있어도 작동하며, 접속한 브라우저가 없거나 저장이 실패하면
  대기 목록을 보관하고 프론트엔드가 시작될 때·패널을 다시 열 때·새 자동 저장 요청이 올 때 재시도한다.
  설정을 꺼도 이미 대기 중인 저장은 재시도한다. 로그인·권한·서버 오류는 한국어로 표시하며 수동 저장은 다시 누를 수 있다.
- http/테일스케일 접속에서도 UUID API 없이 작동한다. 저장 버튼과 설정 스위치는 기존 44px 이상 터치 영역을 사용한다.
- 확인한 호스트 소스에서는 확장 삭제가 소유 이미지를 삭제하지 않고, 채팅 삭제는 이미지의 채팅 소유 정보만 비운다.
  갤러리 연결은 미사용 이미지 정리에서도 이미지를 보호한다. 이 확장 자체는 이미지 파일을 삭제하지 않는다.
  갤러리는 복사본이나 별도 백업이 아니므로 **이미지 자체 또는 캐릭터를 삭제하면 연결도 사라진다**.
  소스 근거와 검증 범위는 [REPORT-gallery.md](REPORT-gallery.md)에 기록했다.

## 0.2.0 변경점

### 패널 개편
- 맨 위 개요 카드(상태 줄 · 요약 칩 · 이 채팅 자동 생성 스위치) 아래에 접이식 구역 4개 — **그림 / 인물 /
  프롬프트 미리보기 / 설정**. 접어 두면 한 줄 요약 배지(예: `2명 · 확인 1`, `깊이 4 · 2장`)만 보여서
  폰에서도 한눈에 볼 수 있다. 펼침 상태는 패널을 닫았다 열어도 유지된다.
- 그림은 타일 격자. 타일을 누르면 상세 화면(큰 그림, 실제로 보낸 긍정/네거티브 프롬프트, 인물 칸별 태그,
  복사 버튼, 다시 그리기)이 열린다. 복사는 `navigator.clipboard`가 없는 http 접속에서도 안 깨진다.
- 인물은 카드형. 이름·**신체 특성**·**옷·장신구**·네거티브를 칸별로 따로 고친다. 삭제는 두 번 눌러야 한다.
- **프롬프트 미리보기**: `chars`와 장면을 넣으면 태그가 어떤 프롬프트(긍정·인물 칸·네거티브)가 되는지
  그림을 그리지 않고 보여 준다. 저장하지 않은 인물 편집도 반영한다.
- 글자 15px 이상(보조 설명 13px 이상), 폰에서 누르는 칸 44px 이상, 안쪽 스크롤 칸 없음, 밝은/어두운 호스트 테마
  모두에서 읽힘(바탕은 `--lumiverse-bg`·`--lumiverse-bg-deep`에서 계산).

### 신체 특성 / 옷·장신구 분리
- 인물마다 외형을 둘로 나눠 저장한다. 프롬프트에는 **신체 특성 → 옷·장신구 → 장면 동작** 순으로 들어간다.
- 0.1.x에서 저장한 합친 외형은 처음 읽을 때 한 번 자동으로 나눈다(보수적 키워드 분류). 애매한 태그는 신체
  쪽에 두고 **"확인해 주세요"** 안내를 띄운다. 그 인물을 저장하면 확인한 것으로 보고 안내가 사라진다.
  나누기 전 원본은 `legacyAppearance`로 남아 패널에서 보고 되돌릴 수 있다. 아무것도 버리지 않는다.
- **이번 장면 옷**: AI가 `chars="이름: 동작 | 옷: black suit, red tie"`처럼 쓰면 그 그림에만 저장된 옷 대신 그 옷이
  쓰인다(신체 특성은 그대로). `옷:`을 안 쓰면 저장된 옷이 쓰인다. 지시문에 이 문법이 포함된다.
- 이 확장은 대화에서 외형을 자동 추출하지 않는다(등록부는 손으로 입력). 그래서 분류는 마이그레이션과 패널의
  "신체/옷 자동 나누기" 버튼에만 쓰인다.

### 네거티브 프롬프트
최종 네거티브 = **메인 프리셋 네거티브 + 공통 네거티브(설정) + 그림에 나온 인물들의 네거티브**, 쉼표 단위로
대소문자 무시 중복 제거. 비어 있지 않으면 항상 명시적으로 보낸다. 전부 비면 보내지 않아 호스트 기본이 그대로 쓰인다.

- **호스트 한계(확인함):** NovelAI V4+ 경로는 모든 인물의 `uc`와 `v4_negative_prompt.char_captions`에 같은 전역
  네거티브를 쓰고, `characterTags` 항목은 `{ tags }`뿐이라 **인물별 네거티브를 따로 전달할 방법이 없다.** 그래서 인물별
  네거티브도 전역 네거티브에 합친다. (루미버스에 인물별 `uc` 지원을 제안해 볼 수 있다.)
- **기본 네거티브가 대체된다:** 우리가 값을 보내면 호스트(NovelAI)의 내장 기본 네거티브는 쓰이지 않는다. 기본 목록을
  유지하려면 설정의 공통 네거티브에 직접 붙여 넣는다. 호스트 값을 코드에 복사하지 않았고, 호스트가 정확한 값을
  노출하지 않아 자동 채우기 버튼은 만들지 않았다.
- **카드·페르소나 연결 네거티브:** 0.1.1은 프리셋의 `{{character_negative_prompt}}`·`{{persona_negative_prompt}}`를
  지우고 호스트의 치환도 끈 채(`skipParse`) 보내서 연결된 네거티브가 한 번도 들어가지 않았고, 프리셋 네거티브가
  그 자리표시자뿐이면 필드를 생략해 호스트가 원문 자리표시자를 그대로 쓰는 경우가 있었다. Spindle은 연결된 프리셋과
  연결 정보를 노출하지 않아 우리가 직접 채울 수 없다. 0.2.0은 기본값(설정의 "카드·페르소나 연결 네거티브 넣기" 켜짐)에서
  그 두 자리표시자를 남기고 `skipParse`를 빼서 **호스트가 채우게** 한다(연결이 없으면 빈칸). 끄면 예전처럼 지우고
  `skipParse`로 보낸다. 연결된 **긍정**(`{{character_prompt}}`·`{{persona_prompt}}`)은 계속 지운다 — 등록부의
  신체/옷 태그가 이미 외형을 넣기 때문에 중복된다.
- 호스트가 채우는 연결 네거티브는 우리 쪽에서 볼 수 없어 중복 제거 대상이 아니고, 미리보기에는 자리표시자 그대로 보인다.

## 권한과 이유

| 권한 | 왜 필요한가 |
|---|---|
| `image_gen` | `spindle.imageGen.generate`로 그림을 그리기 위해 |
| `interceptor` | 답변 생성 전에 `<pic>` 태그 지시문을 끼워 넣고(F1), 과거 메시지 속 그림을 짧은 요약으로 바꿔 보내기 위해(히스토리 정리) |
| `chat_mutation` | 메시지를 읽고(`getMessages`) 태그 자리를 그림으로 고치기 위해(`updateMessage`) |
| `characters` | 캐릭터 카드의 `extensions.lv_illust`에 인물 외형 등록부를 저장/조회하기 위해(F4) |
| `chats` | 지금 채팅이 어느 카드에 속하는지 찾아 그 카드의 등록부를 불러오기 위해(`chats.get`) |
| `generation` | 답변 생성이 끝났다는 이벤트(`GENERATION_ENDED`)를 구독하기 위해 — 이 권한이 없으면 이 이벤트 구독 자체가 호스트에 의해 거부되어 F2(태그 감지)가 전혀 동작하지 않는다 |

여섯 개 모두 admin 승인이 필요한 privileged 권한입니다(1인 개인 서버라면 설치한 본인이 곧 admin).

## 설치

### (a) Import Local — 로컬 폴더로 설치
1. 이 저장소 폴더를 서버의 `data/extensions/lv_illust/repo/`에 복사한다(`설치방법.txt` 참고 — 정확한
   `docker cp` 명령이 적혀 있다).
2. 루미버스에 owner로 로그인 → Extensions(Spindle) 패널 → **Import Local**.
3. 위 여섯 권한을 허용하고 Enable.

### (b) GitHub "Install from Source" — 이 저장소를 GitHub에 올린 경우
1. Extensions 패널 → **Add Extension** → *Install from Source*에 저장소 URL을 붙여넣는다.
2. 같은 권한을 허용하고 Enable.

(지금은 로컬 전용이며 GitHub에 올리지 않았다. 올리게 되면 이 섹션의 절차 그대로 쓸 수 있다.)

## 알려진 한계

- 메시지 속 그림 렌더링 문법(마크다운 이미지 `![...](...)`)이 루미버스 화면에서 실제로 그림으로
  보이는지 실제 서버에서 확인하지 못했다. 설치 후 `<pic prompt="...">` 한 번 써서 꼭 확인할 것.
- 메인 프롬프트 프리셋 합성과 그림체(네이티브 LoRA/스타일) 프리셋 적용 둘 다 코드 경로는 소스로
  확인했지만, 실제 생성 결과에 반영되는지는 실제 서버에서 확인하지 못했다.
- `MESSAGE_EDITED` 이벤트의 payload 모양은 추정이다(타입 정의가 없음). 틀렸다면 조용히 아무 일도
  안 하는 쪽으로 안전하게 실패한다.
- 그림 생성 중 메시지가 수정되거나 스와이프되면, 그 그림은 메시지에 넣지 않고 "넣지 못함" 상태로
  보관해 패널에서 보여준다(자동 재시도 없음, 다시 그리기 버튼도 없음 — 자리를 잃은 그림이라 되돌릴
  데가 없기 때문).
- 같은 메시지에 대한 처리는 직렬화하고, 걸린 작업(3분 넘게 안 끝남)은 잠금을 풀어 다음 작업이
  막히지 않게 한다. 걸렸던 작업은 나중에 다시 움직이더라도 "쓰기 직전"에 반드시 자기가 이미
  시간 초과됐는지 확인하고, 그랬다면 아무것도 쓰지 않고 멈춘다(다른 작업이 그 사이 써 놓은 그림·
  수정·메타데이터를 덮어쓰지 않음 — 검토에서 발견된 회귀를 고친 부분). 다만 호스트 호출 하나를
  기다리는 도중 정확히 그 순간에 시간이 초과되면 그 호출이 끝날 때까지는 멈추지 못한다(끝나자마자
  바로 확인함) — 취소 수단 자체가 없어 완전히 없애지는 못했다. 그림 생성 대기열에도 같은 방식의
  시간제한(5분)을 둬서, 하나가 멈춰도 다른 메시지의 생성까지 막히지 않게 했다.

자세한 근거(파일:줄, VERIFIED/INFERRED/UNVERIFIED)는 `docs/API-NOTES.md`에 있다.
