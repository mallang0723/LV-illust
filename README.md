# 삽화가 (개인용) / LV-Illust

[English](README.en.md)

루미버스(Lumiverse)용 개인 확장. AI가 답변 중간에 `<pic ...>` 태그를 쓰면 그 자리에 NovelAI 그림을
넣고, 인물마다 등록해 둔 외형 프롬프트를 이름으로 찾아 NAI 인물별 프롬프트 칸(`characterTags`)에
넣는다.

> **개인용·비공개입니다.** 재배포·공개 라이선스를 걸어 두지 않았습니다. 사용은 본인(저장소 소유자)과,
> 본인이 직접 저장소를 공유한 대상으로 한정합니다. "배포"가 아니라 "내 서버에 설치"를 전제로 만들었습니다.

## 하는 일

| # | 기능 |
|---|---|
| F1 | 답변 생성 전, "그림이 필요하면 `<pic chars="이름" prompt="장면">` 태그를 써라"는 지시를 프롬프트에 끼워 넣는다. 위치·깊이·역할은 설정에서 고를 수 있다. |
| F2 | 생성이 끝나면 답변에서 `<pic>` 태그를 찾아 하나씩 그림으로 바꾼다. 한 답변당 최대 2장(설정 가능), 넘는 태그는 "건너뜀" 표시. 형식이 깨진 태그는 **원문을 절대 지우거나 요약하지 않고 그대로 둔 채** 바로 옆에 짧은 표시만 덧붙인다(메시지 길이는 줄지 않는다). |
| F3 | 태그 속 이름을 등록부에서 찾아(별칭 여러 개, 긴 이름부터, 대소문자·띄어쓰기 무시, 실제 띄어쓰기 경계가 있을 때만 부분일치 허용) 외형 프롬프트로 바꾸고 NAI 인물 칸으로 보낸다. 등록 안 된 이름·꺼 둔 인물은 AI가 쓴 묘사만으로 그린다. |
| F4 | 캐릭터 카드마다 인물 외형 등록부(이름들·외형·켜기/끄기)를 둔다. 같은 카드의 모든 채팅이 공유한다. 등록부는 **빈 상태로 시작**하며, 미리 채워 둔 이름은 없다. |
| F5 | 그림을 메시지 속 태그 자리에 그대로 넣는다(`chat.updateMessage`). 실패/상한 초과는 각각 다른 표시로 남고, 원본 정보는 메시지 메타데이터에 보관되어 복구 가능하다. 생성은 루미버스의 `imageGen.generateNative`(사용자 지정 그림체 프리셋 반영)로 요청한다. |
| F6 | 입력창 버튼 "삽화가 설정" 패널에서 이 채팅에 그려진 그림 목록을 보고 "다시 그리기"를 누를 수 있다. 생성 중 메시지가 바뀌어(수정·스와이프) 그림을 넣을 자리가 사라지면, 그림을 버리지 않고 같은 패널에 상태/사유만(재시도 버튼 없이) 남겨 둔다. |

메인 프롬프트·그림체 프리셋·장면 자동 생성 같은 루미버스 기본 기능은 그대로 쓴다 — 이 확장은
"답변 속 그림 태그" + "인물별 외형 등록"만 더한다.

## 권한과 이유

| 권한 | 왜 필요한가 |
|---|---|
| `image_gen` | `spindle.imageGen.generate`로 그림을 그리기 위해 |
| `interceptor` | 답변 생성 전에 `<pic>` 태그 지시문을 끼워 넣고(F1), 과거 메시지 속 그림을 짧은 요약으로 바꿔 보내기 위해(히스토리 정리) |
| `chat_mutation` | 메시지를 읽고(`getMessages`) 태그 자리를 그림으로 고치기 위해(`updateMessage`) |
| `characters` | 캐릭터 카드의 `extensions.lv_illust`에 인물 외형 등록부를 저장/조회하기 위해(F4) |
| `chats` | 지금 채팅이 어느 카드에 속하는지 찾아 그 카드의 등록부를 불러오기 위해(`chats.get`) |
| `generation` | 답변 생성이 끝났다는 이벤트(`GENERATION_ENDED`)를 구독하기 위해 — 이 권한이 없으면 이 이벤트 구독 자체가 호스트에 의해 거부되어 F2(태그 감지)가 전혀 동작하지 않는다 |

여섯 개 모두 admin 승인이 필요한 privileged 권한입니다(1인 개인 서버라면 설치한 본인이 곧 admin).

## 설치

### (a) Import Local — 로컬 폴더로 설치
1. 이 저장소 폴더를 서버의 `data/extensions/lv_illust/repo/`에 복사한다(`설치방법.txt` 참고 — 정확한
   `docker cp` 명령이 적혀 있다).
2. 루미버스에 owner로 로그인 → Extensions(Spindle) 패널 → **Import Local**.
3. 위 여섯 권한을 허용하고 Enable.

### (b) GitHub "Install from Source" — 이 저장소를 GitHub에 올린 경우
1. Extensions 패널 → **Add Extension** → *Install from Source*에 저장소 URL을 붙여넣는다.
2. 같은 권한을 허용하고 Enable.

(지금은 로컬 전용이며 GitHub에 올리지 않았다. 올리게 되면 이 섹션의 절차 그대로 쓸 수 있다.)

## 알려진 한계

- 메시지 속 그림 렌더링 문법(마크다운 이미지 `![...](...)`)이 루미버스 화면에서 실제로 그림으로
  보이는지 실제 서버에서 확인하지 못했다. 설치 후 `<pic prompt="...">` 한 번 써서 꼭 확인할 것.
- `imageGen.generateNative`가 사용자의 그림체(네이티브 LoRA/스타일) 프리셋을 실제로 프롬프트에
  붙이는 코드 경로는 소스로 확인했지만, 실제 생성 결과에 반영되는지는 실제 서버에서 확인하지 못했다.
- `MESSAGE_EDITED` 이벤트의 payload 모양은 추정이다(타입 정의가 없음). 틀렸다면 조용히 아무 일도
  안 하는 쪽으로 안전하게 실패한다.
- 그림 생성 중 메시지가 수정되거나 스와이프되면, 그 그림은 메시지에 넣지 않고 "넣지 못함" 상태로
  보관해 패널에서 보여준다(자동 재시도 없음, 다시 그리기 버튼도 없음 — 자리를 잃은 그림이라 되돌릴
  데가 없기 때문).

자세한 근거(파일:줄, VERIFIED/INFERRED/UNVERIFIED)는 `docs/API-NOTES.md`에 있다.

