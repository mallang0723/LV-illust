알려진 한계 (docs/API-NOTES.md 참고)
- 메시지 속 그림 렌더링 문법(마크다운 이미지)이 루미버스 화면에서 실제로 그림으로 보이는지 미시험.
  실제 서버에서 <pic prompt="..."> 한 번 써 보고 확인 필요 (DESIGN.md §6 "만들기 전 첫 작업"에 해당).
- MESSAGE_EDITED 이벤트의 payload 모양을 추정함(실제 수정으로 확인 안 함) — 단, 신뢰하는 필드는
  chatId/message.id뿐이고 나머지(내용·메타데이터·is_user)는 전부 chat.getMessages로 다시 읽어 확인하므로,
  추정이 틀려도 조용히 아무 일도 안 함(안전하게 실패)이지 다른 확장 메타데이터를 덮어쓰지 않음.
- registerMessageAction(말풍선 버튼)은 존재를 확인했지만 이번 MVP엔 안 씀 — 패널의 "다시 그리기" 목록만.

검토 이력 메모
1차(자체 검토, advisor): "generation" 권한을 빠뜨려 GENERATION_ENDED 구독 자체가 막히는 치명적 버그
  (worker-host.ts의 handleSubscribeEvent가 생성 관련 이벤트를 generation 권한으로 게이트), 형식 오류
  마커가 '<'를 이스케이프하지 않아 재처리 시 무한 증식하는 버그, 인터셉터가 멀티모달(배열) content를
  문자열화해 버리는 버그, imageGen.generate 동시 호출 상한(1)이 실제로는 강제되지 않던 문제,
  MESSAGE_EDITED 처리가 검증 안 된 payload 필드를 그대로 신뢰하던 문제 — 전부 발견·수정, 테스트로 고정.

2차(독립 검토, Codex): 7건 전부 코드 대조 결과 실제 버그로 확인되어 전부 수정(기각 0건).
  - 블로커 2건: (1) 그림 생성 대기 중 메시지가 바뀌면 그 변경을 되돌려 쓰던 경쟁 상태 — 쓰기 직전에
    메시지를 다시 읽고, 태그 원문으로 현재 내용 속 위치를 다시 찾고, 스와이프가 바뀌었으면 아예 쓰지
    않고 "넣지 못함" 상태로 보관(lv_illust.orphans)하도록 수정. (2) 형식이 깨진 태그 복구 로직이 다음
    '<'나 메시지 끝까지를 통째로 집어삼켜(실측 사례: 뒤따르는 서사 문단이 통째로 날아감) 200자 요약으로
    뭉개 버리던 버그 — 가장 가까운 '>'를 우선 경계로 쓰고, 그래도 없으면 300자로만 제한하도록 수정.
  - 메이저 2건: (3) 빈 등록부에서 "+ 인물 추가"가 이름 없는 항목을 즉시 저장해 서버 쪽 정규화가
    버려버려 아무 일도 안 하던 버그(등록부가 빈 상태로 시작해야 하는 요구사항과 정면으로 충돌) — 이름을
    넣기 전까지는 로컬 임시 행으로만 두도록 수정. (4) 패널이 카드를 바꿔 가며 빠르게 열고 닫으면 먼저
    보낸(이미 낡은) 요청의 응답이 나중에 도착해 새 카드의 화면·데이터를 덮어쓰던 경쟁 상태 — 매 열기마다
    토큰을 올리고, 낡은 토큰의 응답은 버리고, 읽기가 성공하기 전엔 쓰기(저장·토글·다시 그리기)를 막도록
    수정.
  - 마이너 3건: (5) 별칭 부분일치 보정이 공백 없이 "Anna"가 "Ann"에 걸리던 버그 — 실제 띄어쓰기 경계를
    요구하도록 수정. (6) 실패/건너뜀 표시에 넣은 원문이 '>'를 포함하면 정규식이 거기서 멈춰 다시
    그리기·히스토리 정리가 깨지던 버그 — 표시에는 id만 남기고(원문은 이미 메타데이터에 있음) 공용 정규식
    하나로 통일. (7) 등록부 이름에 줄바꿈이 섞여 들어가면 지시문에 그대로 꽂히던 문제 — 제어문자 제거 +
    길이 제한 + 따옴표로 인용해 표시하도록 수정.
  전부 회귀 테스트 추가(핵심 로직 54개 + 백엔드 25개 + 프론트 10개 = 89개, 전부 통과).

3차(독립 검토, Codex, 호스트 소스 열람 포함): 2차 수정 중 2건이 불완전했음을 재현으로 확인, 신규 3건
  추가 발견. 7건 전부 코드 대조로 실제 버그 확인, 전부 수정(기각 0건).
  - 블로커 2건: (1-재현) 형식 오류 복구 로직의 '다음 < 로 이동' 분기에 300자 상한이 적용 안 돼 있어서,
    깨진 태그 뒤에 긴 서사 + (전혀 상관없는) 나중 '<' 하나만 있어도 그 사이 전부가 통째로 날아감
    (실측 2,030→230자). 근본 원인은 "마커로 교체" 설계 자체 — 이번엔 원문을 절대 지우거나 바꾸지 않고
    원문 뒤에 짧은 표시만 "끼워 넣는" 방식으로 바꿈(메시지 메타데이터에 malformedSeen 기록해 같은 깨진
    태그를 두 번 표시하지 않음). (2) 고아 보관(pushOrphans)을 "메시지 다시 읽기"와 "쓰기" 사이에
    await해서 경쟁 상태를 다시 열어 버린 문제 — 쓰기를 먼저 하고 고아 보관은 그 다음으로 순서 변경.
  - 메이저 3건: (3) GENERATION_ENDED와 MESSAGE_EDITED가 같은 메시지에 거의 동시에 들어오면 각자
    따로 계획을 세워 같은 id("p1")를 중복 할당하고 서로의 기록을 덮어쓰던 문제 — (채팅,메시지)별 잠금으로
    계획→생성→커밋 전체를 직렬화하고, id 생성도 순차가 아니라 충돌 방지(시간+난수) 방식으로 교체.
    (4) 그림 생성 API가 성공을 반환해도 실제 그림 URL이 없을 수 있는데(호스트가 저장 실패를 삼키고도
    성공 응답) 이를 그대로 "성공"으로 기록해 `(undefined)` 그림이 들어가던 문제 — URL 없으면 실패로
    처리, 다시 그리기는 검증 전엔 기존 그림을 건드리지 않도록 수정. (5) `imageGen.generate`는 루미버스
    네이티브 그림체(스타일/LoRA) 프리셋을 전혀 적용하지 않음(설계 원칙 위반) — 소스 직접 확인 후
    `imageGen.generateNative`(promptMode:'custom', skipParse:true)로 교체: 네이티브 프리셋은 적용되고
    장면 분석이 꺼져 있어 우리 characterTags는 그대로 보존됨을 코드로 확인(docs/API-NOTES.md에 근거
    파일:줄 전부 기록).
  - 마이너 2건: (6) 고아(자리를 잃은) 그림에도 "다시 그리기" 버튼이 떠서 눌러도 실패하거나(3번 버그와
    겹치면) 엉뚱한 기록을 건드릴 수 있었음 — 고아는 상태/사유만 보여주고 버튼은 아예 없앰. (7) 채팅별
    자동생성을 꺼도 히스토리 정리(렌더된 그림을 요약으로 바꾸는 것)까지 같이 꺼지던 문제 — 지시문
    끼워넣기만 자동생성에 묶고, 히스토리 정리는 항상 실행하도록 분리.
  - 보너스: 별칭에 포함된 따옴표(")가 이스케이프 안 돼 지시문 인용 표시가 깨질 수 있던 문제도 같이 수정.
  전부 회귀 테스트 추가(103개 전부 통과: 핵심 로직 59 + 백엔드 33 + 프론트 11).
