알려진 한계 (docs/API-NOTES.md 참고)
- 메시지 속 그림 렌더링 문법(마크다운 이미지)이 루미버스 화면에서 실제로 그림으로 보이는지 미시험.
  실제 서버에서 <pic prompt="..."> 한 번 써 보고 확인 필요 (DESIGN.md §6 "만들기 전 첫 작업"에 해당).
- MESSAGE_EDITED 이벤트의 payload 모양을 추정함(실제 수정으로 확인 안 함) — 단, 신뢰하는 필드는
  chatId/message.id뿐이고 나머지(내용·메타데이터·is_user)는 전부 chat.getMessages로 다시 읽어 확인하므로,
  추정이 틀려도 조용히 아무 일도 안 함(안전하게 실패)이지 다른 확장 메타데이터를 덮어쓰지 않음.
- registerMessageAction(말풍선 버튼)은 존재를 확인했지만 이번 MVP엔 안 씀 — 패널의 "다시 그리기" 목록만.

  - 메이저(4차 "형식 오류" 구조적 수정이 여전히 불완전) 1건: 정확히 `<pic prompt="unfinished`
    (뒤에 아무것도 없는, 가장 짧은 형태)가 여전히 10번 쓰기 + 중첩 표시를 일으킴 — 깨진 태그의
    "닫히지 않은 값" 스캔이 따옴표나 '<'에서만 멈추는데 우리 표시 문구엔 둘 다 없어서, 두 번째
    처리부터 이전에 붙인 표시 문구를 "아직 안 끝난 값의 일부"로 읽어 버려 매번 표시를 붙이는
    위치가 바뀌는 바람에 "표시가 바로 뒤에 있는지" 검사가 계속 엉뚱한 자리를 봄. 요청대로 더
    구조적으로 고침: 표시 문구를 리터럴 `<pic` 바로 뒤(네 글자 뒤, 태그의 다른 속성 텍스트보다도
    앞)에 끼워 넣고, 표시 문구 자체가 공백도 '>'도 아닌 글자(⟦)로 시작하게 바꿈 — 그러면 파서의
    첫 번째 검사("<pic 다음 글자가 공백이나 '>'가 아니면 우리 태그가 아님")에서 이미 걸러져서,
    한 번 표시된 자리는 다시는 "<pic 태그"로조차 인식되지 않음(이전부터 `<pic-failed` 같은 걸
    걸러내던 바로 그 규칙). 덕분에 문제였던 "닫히지 않은 값 스캔"이 다시 호출될 일 자체가 없어짐.
    이 작업 중 백엔드 쪽에서 별도의 실수도 발견: core.mjs의 파싱/적용 로직은 이미 올바르게
    고쳤는데, backend.mjs 자체의 이어붙이기 루프가 옛날 계산식(`위치 + 전체길이`)을 그대로 쓰고
    있어서 통합 테스트에서만 재현되는 회귀가 남아 있었음 — 직접 발견해 같이 수정.
  전부 회귀 테스트 추가(129개 전부 통과: 핵심 로직 72 + 백엔드 46 + 프론트 11). 핵심 로직에는
  무작위 시드 기반 퍼즈 테스트(40회 반복, 정상/깨진/안 끝난/중첩 태그 뒤섞임, 20회 연속 처리)도
  포함.
